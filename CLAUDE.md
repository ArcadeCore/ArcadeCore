# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview
ArcadeCore is a Spigot/Paper Minecraft plugin (group `org.drappula`, one jar for Minecraft 1.8 to 26.3) providing core lobby/arcade-server functionality: a game/match/queue framework, a SQLite-backed arena map pool, per-player profiles, and a SQLite-backed user data store. It is split into two Gradle subprojects:
- **ArcadeAPI** (version `1.1.0`) - a `java`-only module of public interfaces/events other plugins depend on to integrate with ArcadeCore (package `org.drappula.arcadeApi`). Contains no core implementation. It also holds the shared message layer (`message/Messages`, `LegacyText`, `ScreenText`). No paper-api or Adventure types appear in it.
- **ArcadePlugin** - the actual plugin (`java-library`), package `org.drappula.arcadeCore`, implements every `ArcadeAPI` interface and is what gets shaded into the runnable jar.

## Build & run commands
Run from the `ArcadeCore/` root (this is the Gradle root project; `ArcadeAPI`/`ArcadePlugin` are subprojects). Do not run Gradle here while another repo's build is running; addons `includeBuild` this directory and share its `build` folder.
- `./gradlew build` - compiles both modules, runs tests, and produces the shadowed plugin jar (shadowJar runs as part of `build`).
- `./gradlew :ArcadePlugin:shadowJar` - build the dependency-bundled jar directly (`ArcadePlugin/build/libs/ArcadePlugin-1.0.0-all.jar`).
- `./gradlew test` (or `:ArcadePlugin:test`, `:ArcadeAPI:test`) - JUnit 5 + Mockito, plus MockBukkit in `ArcadePlugin`. TDD is required, see `AGENTS.md`.
- There is no `runServer` task (run-paper was removed). For manual testing drop the jar into any 1.8 to 26.3 server's `plugins/`, or use `../TestServer-matrix` (`matrix.sh` boots six versions with the current jars).

## Architecture
- **Language/toolchain**: Java, built with Gradle Kotlin DSL on a JDK 21 toolchain, but production sources compile with `--release 8` against `spigot-api:1.8.8-R0.1-SNAPSHOT` (`compileOnly`) so the jar loads on Java 8 servers. Tests use JDK 21 and MockBukkit v1.21. No Kotlin sources and no Kotlin plugin. Production code must stay version-neutral: no Paper-only API, Adventure, Brigadier, SLF4J logger, or Java 9+ features (see `AGENTS.md`).
- **Shadow/relocation**: `com.gradleup.shadow` (applied only in `ArcadePlugin`) bundles `dev.dejvokep:boosted-yaml` (+ `boosted-yaml-spigot`), `XSeries` and `org.xerial:sqlite-jdbc`. XSeries is relocated to `org.drappula.arcadeCore.libs.xseries`. `mergeServiceFiles()` keeps the sqlite JDBC service entry, and `Database.connect` also does `Class.forName("org.sqlite.JDBC")`. Nothing is downloaded at runtime; there is no loader class.
- **Plugin entry point**: `ArcadeCore` (`ArcadePlugin/src/main/java/org/drappula/arcadeCore/ArcadeCore.java`) is a singleton accessible via `ArcadeCore.get()`. `onEnable()` runs, in order: `Messages.useScreenText(new XSeriesScreenText())`, `setupConfig()` (loads `DataConfig`, `MainConfig`, `MessagesConfig`), `connectDatabase()` (opens the SQLite connection, throws on failure), `MapManager.get().load()` (reads the map pool from the database), `ArenaWorldManager.destroyOrphanedArenas()`, `registerCommands()` (`getCommand("arcade")` executor + tab completer, declared in `plugin.yml`), `registerListeners()`, a 30 s arena sweeper task, `registerAPI()` (publishes `ArcadeAPIImpl` through `ArcadeAPIProvider`). `onDisable()` reloads `GameManager` (clears in-memory game/match/participant state), destroys leftover arena worlds, releases all maps (`MapManager.releaseAll()`, clearing `in_use` flags in memory and DB), and disconnects the database.
- **API/impl split**: Every cross-cutting system is defined as an interface in `ArcadeAPI` (`IGameManager`, `IMatchManager`, `IQueueManager`, `IMapManager`, `IMatch`, `IParticipant`, `IArcadeMap`) and implemented as a singleton (`X.get()` static accessor, lazily constructed) in `ArcadePlugin`'s `managers/` package (`GameManager`, `MatchManager`, `QueueManager`, `MapManager`, `Match`, `Participant`, `ArcadeMap`). `ArcadeAPIImpl` (`ArcadePlugin/.../api/ArcadeAPIImpl.java`) is the single class that bridges the two, registered once in `ArcadeCore#onEnable`. When adding a new cross-plugin-facing feature, add the interface/event to `ArcadeAPI` first, then wire the concrete manager and expose it through `ArcadeAPIImpl`.
- **Game/match/queue flow**: `GameManager` holds registered `Game`s plus in-memory `matches`/`participants` maps keyed by game ID (no persistence - cleared on `reload()`, called from `onDisable`). `QueueManager.joinQueue` fires a cancellable `QueueEnterEvent`; when a queue reaches `game.getMinPlayers()` a `QueueCountdownTask` starts (`queue.start-countdown` in `MainConfig`, default 20 s, ticks 1 s), which starts the match when it expires - or immediately once the queue reaches `game.getMaxPlayers()`. Dropping below the minimum (via `leaveQueue`) cancels the countdown. `startQueuedMatch` slices up to `getMaxPlayers()` players off the queue and calls `MatchManager.startMatch`, which can return **null** - if `game.createArena(players)` returns null it acquires a map from `MapManager` (none available → null; the sliced players are put back at the front of the queue, the countdown restarts at threshold, and they get the `map-unavailable` message), then bails if the map has fewer spawn points than players, then fires a cancellable `MatchStartEvent` (cancelled → depopulate + release map + null). On success it teleports each player to a spawn point and starts `MatchStartTask` (repeating `BukkitRunnable`, countdown from `match.start-countdown` in `MainConfig`, ticks every 20 ticks/1s). Matches carry a `MatchState` (`LOADING → STARTING → STARTED → ENDING → ENDED`), advanced by `startMatch`/`MatchStartTask`/`endMatch`/`MatchEndTask`. `Match.end()` → `MatchManager.endMatch` fires `MatchEndEvent` and starts `MatchEndTask`, which eliminates all remaining participants immediately (via `MatchManager.eliminateParticipant`, which applies `GameEndSettings` gamemode/fly overrides or config defaults), then - 5 seconds later - depopulates the match, releases its map, and sends spectators back to the lobby. Addons declare winners with `setWinnerParticipants(...)` or `endWithWinners(...)`; teardown records +1 win for winners and +1 loss for the rest, and skips stats when no winners were declared.
- **Map pool**: `MapManager` (`managers/map/`) keeps an in-memory `List<ArcadeMap>` loaded from SQLite at enable via `MapDataManager` (`database/MapDataManager.java`, raw JDBC against the `maps` + `map_spawns` tables); maps whose world isn't loaded are skipped with a warning. `acquireMap(gameId)` returns the first map that is enabled, not in use, and has ≥1 spawn point, flagging it `in_use` both in memory and in the DB (so a crash doesn't leak maps forever - `releaseAll()` on disable clears the flags). All mutations (`createMap`, `addSpawn`, `setEnabled`, `deleteMap`) write through to the DB and update the in-memory list. Maps are administered entirely in-game via `/arcade map ...` - there is no file-based map config.
- **Config layer**: Config classes extend `Config` (`config/Config.java`), which wraps `dev.dejvokep.boostedyaml.YamlDocument` with `SpigotSerializer` (so Bukkit types like `Location` (de)serialize directly) and `BasicVersioning` keyed on a `version` field for auto-updating the file to the packaged default. Three configs, each with a static `setup()`/`get()`:
  - `DataConfig` (`data.yml`) - runtime/mutable state (currently just `SPAWN_LOCATION`, via `setSpawnLocation`/`getSpawnLocation`).
  - `MainConfig` (`config.yml`) - admin-facing settings, e.g. `lobby.teleport-spawn`, `lobby.gamemode`, `match.start-countdown`, `match.end.gamemode`, `match.end.fly-enabled`, `queue.start-countdown`.
  - `MessagesConfig` (`messages.yml`) - all player-facing text (e.g. `match-started`, `countdown-message-singular`/`-plural`, `participant-eliminated`, `match-ended`, `map-unavailable`, `map-created`, `map-not-found`, `bad-arguments.unknown-game`), sent via `MessageUtil.sendMessage`, which delegates to `Messages` in `ArcadeAPI` (`prefix:text;prefix:text` strings, `<name>` placeholders from key/value varargs, a MiniMessage subset translated to section-sign codes by `LegacyText`; titles and action bars via XSeries; boss bars degrade to an action bar).
- **Commands**: `MainCommand` is a plain Bukkit `CommandExecutor` + `TabCompleter` (no Brigadier) for `/arcade`, declared in `plugin.yml`: bare `/arcade` prints plugin name/version/description; `reload` reloads `DataConfig`, `MainConfig`, and `MessagesConfig`; `setspawn` saves the invoker's location; `start <game>` (requires `arcade.force-start` permission) force-starts a match via `QueueManager.forceStart`; `queue <game>` (player-only) joins the queue via `QueueManager.joinQueue` with `queue-joined`/`queue-denied` feedback; `map create|addspawn|enable|disable|list|delete|config` (requires `arcade.map.admin` permission) administers the map pool - `create` uses the invoker's current world, `addspawn` the invoker's exact location, `config` sets per-map addon options.
- **Database**: `Database` (`database/Database.java`) opens a single static SQLite connection to `<plugin-data-folder>/database.db` on enable (with `PRAGMA foreign_keys = ON`) and creates six tables if absent: `user_profiles` (uuid, username), `games` (game_id), `game_stats` (uuid, game_id, points, wins, losses, other_stats JSON - FKs cascade-delete), `maps` (map_id, game_id, display_name, world, enabled, in_use), `map_spawns` (map_id + spawn_index PK, x/y/z/yaw/pitch - cascade-deletes with its map), and `map_config` (per-map addon option overrides - cascade-deletes with its map). `user_profiles` is read/written via `UserDataManager` (`get`/`getOrCreate`/`save`, upsert on conflict), `maps`/`map_spawns` via `MapDataManager` - `games`/`game_stats` are written by `GameStatsManager.recordMatchResult` on match teardown (winners +1 win, other participants +1 loss; skipped when the addon declared no winners).
- **Listeners**: `LobbyListener` handles `PlayerJoinEvent` - registers a `Profile`, teleports to `DataConfig`'s saved spawn (if `lobby.teleport-spawn` is enabled), resets health to max, sets gamemode from `MainConfig` - and `PlayerQuitEvent` - leaves any queue, eliminates the player from any match they're still alive in, removes them from spectator lists, and removes the `Profile`.
- **Profiles**: `ProfileManager` is a simple in-memory `UUID -> Profile` map (register/get/remove) separate from the persisted `UserData`/`user_profiles` table - it's runtime session state, not database-backed.
- **Resource filtering**: `plugin.yml` uses Gradle `processResources` token expansion for `${description}`/`${version}`, sourced from `gradle.properties`.
